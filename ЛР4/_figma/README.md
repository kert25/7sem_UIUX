# Figma-плагин «Fleur Builder»

Строит в Figma весь макет ЛР4: шесть экранов, три листа графической разметки,
карту сайта и дизайн-систему. Цветовые и текстовые стили создаются в файле,
иллюстрации букетов — векторные, из генератора `site.js`.

## Как запустить

1. Открыть Figma Desktop, войти в аккаунт, открыть (или создать) файл.
2. `Ctrl + /` → **Import plugin from manifest…** → выбрать
   `_figma/plugin/manifest.json`.
3. Снова `Ctrl + /` → **Fleur Builder** (раздел Development) → **Run**.
4. Через несколько секунд появятся страницы:
   - `01 Макет` — 6 экранов;
   - `02 Разметка` — главная, конструктор, мобильная версия;
   - `03 Карта сайта` — структура и сценарии;
   - `04 Дизайн-система` — сетка, палитра, типографика, компоненты.

Повторный запуск перезаписывает эти страницы (ищет их по имени) и заново
создаёт стили: перед сборкой плагин удаляет свои прежние стили `Цвет/…` и
`Текст/…`, иначе Figma не даёт создать стиль с занятым именем. Служебная
страница тоже ищется по имени, а её дубли удаляются — раньше текущая страница
переименовывалась в «00 Служебное», и при каждом прогоне в файле оставалась
лишняя пустая страница (текущую страницу Figma удалять не даёт, поэтому сначала
переключаемся на свою).

## Выгрузка PNG для отчёта

Плагин сам экспортирует кадры и отправляет их на локальный приёмник.

```powershell
node _figma/export_server.mjs     # слушает 127.0.0.1:8765, пишет в _figma/figma_export
```

Сервер должен быть запущен **до** запуска плагина. Если сервера нет — плагин
всё равно построит макет, просто напишет «экспорт не выполнен». Кадры из
`figma_export` и есть рисунки отчёта (`ЛР4/screenshots` — их копии под
нужными именами).

## Сборка

`code.js` — генерируемый файл, руками не правится:

```powershell
node _figma/build_plugin.mjs      # site.js → SVG букетов + части плагина → code.js
node _figma/mock_figma.mjs        # прогон на моке Figma API (проверка ошибок)
node _figma/render_mock.mjs       # SVG-превью кадров в _figma/preview (локально, в git не хранится)
```

Части плагина лежат в `_figma/plugin/parts`: `00_head.js` (помощники, шапка,
подвал), `10_pages.js` (экраны), `20_boards.js` (разметка, карта, система),
`90_run.js` (сборка файла и экспорт).

## Особенности API, на которые пришлось подстроиться

- экспорт кадра — метод узла: `frame.exportAsync({ format: "PNG" })`;
- у `TextStyle` в текущей Figma нет свойства `fills`, цвет задаётся на текстовом
  слое, а текстовый стиль несёт только шрифт, размер и интерлиньяж;
- в режиме `documentAccess: "dynamic-page"` переключение страницы идёт через
  `figma.setCurrentPageAsync`, а `children` чужой страницы доступны после
  `page.loadAsync()`;
- `networkAccess.allowedDomains` принимает имя хоста: `http://localhost:8765`
  (IP-адрес в этом поле отклоняется);
- прогон на моке (`mock_figma.mjs`) проверяет только логику построения —
  реальную вёрстку смотреть в Figma, мок её не воспроизводит.
